# CLAUDE.md - Infra-Brand-Identity

Источник правды по айдентике внутренних сервисов GG. Перед любой работой с логотипом, фавиконами, цветами или шапкой внутреннего сервиса читай `README.md` (раздел «Правила»).

- Файлы бери из `assets/`, не рисуй логотип и фавиконы заново, не перекрашивай `global-logo` в другие цвета кроме navy/белого.
- Подпись сервиса: вариант 2 «Во всю высоту» (линия во всю высоту логотипа, Montserrat 600 navy). Решения Лёва не пересматривать без его запроса.
- Фавиконы (с 07.10.2026): только из `assets/favicons/`. Клиентские = фавикон сайта global-generations.com на своём синем фоне; внутренние = один светлый фон (как у анкеты) и крупная белая иконка сервиса; корень = фавикон сайта как есть. Старые плитки с lucide запрещены, Лёву они «пиздец как не нравятся». SAT и IELTS теперь Aura, не GG.
- Экран входа: над «Вход для команды» никакой иконки (ни замка, ни плашки). Сервис подписан у логотипа.
- Джи-джи: только `assets/gigi/gigi-mascot.png` как есть. Никогда не превращать в плитку/иконку/градиент.
- Правка страницы: `src/template.html` → `python3 src/build.py` → `python3 src/check.py` (0 горизонтальной прокрутки, 0 ошибок, 0 длинных тире). Большие HTML не редактировать строковыми заменами в `index.html`: он генерируется.
- Экраны входа и кнопка «Войти через GG ID»: только кит `gg-id/` (правила в `gg-id/README.md`). Правка: `gg-id/gg-id.css` или `src/gg_id/screens.html` → `python3 src/build_gg_id.py` → `uv run --with playwright python src/check_gg_id.py`. `gg-id/screens/*` и `gg-id.html` генерируются. Правка кита = новая версия: `gg-id/VERSION`, `version` в `gg-id.js` и `gg-id-service.js`, шапки `gg-id.css`, `gg-id.js` и `account-menu/gg-account-menu.js` (сборка сверяет).
- Сцена экрана входа (Лёв 10.10: «после первого клика экран меняется, фон и геометрия ломаются»): `gg-id/gg-id-stage.css`, добавочный файл ПОСЛЕ `gg-id.css` на каждой странице раскладки `split`. Один файл на хаб, ворота и все сервисы GG: заголовок на `max(28 px, (высота окна - 560 px) / 2)` в любом виде любого сервиса, подвал в две строки со ссылкой «Как войти: инструкция». Это контракт: в сервисах лежит копия байт в байт, sha256 закреплён в `src/build_gg_id.py`, `src/check_gg_id_stage.py` и `gg-id/README.md`; файл руками не править, правка = новый файл, новый sha256, новая версия кита и PR во все копии. Закреплённые копии `gg-id.css` у сервисов из-за сцены не обновляются. Проверка: `python3 src/check_gg_id_stage.py` (без браузера, идёт в CI) и `uv run --with playwright python src/check_gg_id_stage.py --browser` (идёт в CI и в `check_gg_id.py`).
- Вход по ключу везде «Face ID / Touch ID», всегда со слэшем (Лёв 10.10: «Face ID это не всегда Face ID, иногда Touch ID», «пиши всегда слеш»), сам ключ «passkey»: одиноких «Face ID» и «Touch ID» нет нигде. Подписи не угадывают устройство по браузеру (Лёв 09.10): Windows Hello, «отпечаток» и «палец» только когда в ЭТОМ браузере уже входили своим ключом (localStorage `gg-id-local-key`, `gg-id-last-method`, `gg-id-local-miss`, `gg-id-enroll-skip`; имена общие со страницей входа хаба и страницами подтверждения Face ID / Touch ID для админов (Infra-AWS, Infra-Auth), переименовать можно только везде сразу). Иначе: «Face ID / Touch ID» на телефоне (QR-код) или ключ на этом устройстве. В разметке экранов нет одиноких слов и слов про способ одного устройства (сборка не пустит), слова ставит `gg-id.js`. Правило и API: `gg-id/HANDOFF-AUTH.md`, раздел 6.1. Проверка: `src/check_gg_id_passkey.py` (идёт и в `check_gg_id.py`).
- Меню аккаунта сервисов (чип с инициалами, значок Add to Apple Wallet, «Мои сервисы», «Профиль GG ID», «Выйти»): только кит `gg-id/account-menu/` (`GGAccountMenu`, правила и сниппеты в `gg-id/account-menu/README.md`). Адреса хаба по умолчанию лежат в константе `HUB` кита, сервисы их не пишут. Значок Wallet нарисован временно: Apple требует свой файл значка (`walletImage`), его скачивает человек, приняв лицензию Apple, агент её не принимает. Правка вида: `gg-id/gg-id.css` или `src/account_menu/local.css` → `python3 src/build_account_menu.py` → `uv run --with playwright python src/check_account_menu.py`. `gg-account-menu.css` генерируется, руками не править.
- Язык текстов страницы - русский, кода и коммитов - английский. Без эмодзи и длинных тире.
- Внешние CDN шрифтов запрещены (Montserrat самохостом в `src/fonts.css`).

## Ключи API (правило организации Global-Generation)

Перед любой работой с ключами API (OpenRouter и другие): взять ключ, завести новый, сменить, разобраться с расходом или ошибкой 401/403 от провайдера, сначала открыть репо [Global-Generation/Infra-API-Keys](https://github.com/Global-Generation/Infra-API-Keys) и сверить:

- `docs/RULES.md`: какой ключ брать. 1 сервис = 1 ключ с месячным капом, прод и дев на разных ключах, ключ другого сервиса не брать никогда; агент Claude для своих задач берёт только `gg-claude-agents` или `gg-yt-scripts`.
- `docs/KEY-MAP.md`: какой ключ у какого сервиса, сколько тратит и где прописан.
- `docs/RUNBOOK.md`: как завести, сменить и вывести ключ без поломок.

Значения ключей лежат только в AWS Secrets Manager (`gg/<сервис>/openrouter-api-key`): в репо, чатах и логах их не бывает. Не ясно, какой ключ брать = спросить Лёва. После любого изменения ключа обновить в Infra-API-Keys `docs/KEY-MAP.md` и `docs/HISTORY.md`.
